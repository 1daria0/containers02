## Описание выполнения работы

### Этап 1. Подготовка и работа в PowerShell

* Скачала дистрибутив Debian для серверов для архитектуры x64 (без графического интерфейса) и систему виртуализации (гипервизор) QEMU.

* Создала репозиторий `containers02` и склонировала его на локальный компьютер:

```
git clone https://github.com/1daria0/containers02
```

* Создала папку для установочного образа:
```
mkdir dvd
```

* Скопировала файл Debian в папку dvd:
```
copy C:\Users\Admin\Downloads\debian-13.3.0-amd64-netinst.iso dvd\debian.iso
```

* Создала файл `.gitignore`:
```
notepad .gitignore
```

* В открывшемся блокноте написала:
```
# Игнорируемые файлы
*.qcow2
*.iso
*.zip
```

* Создала виртуальный жесткий диск размером 8 ГБ:
```
qemu-img create -f qcow2 debian.qcow2 8G
```

* Установила ОС Debian на виртуальную машину:
```
qemu-system-x86_64 -hda debian.qcow2 -cdrom dvd/debian.iso -boot d -m 2G
```

При установке использовала следующие параметры:

* Имя компьютера: `debian`
* Доменное имя: `debian.localhost`
* Имя пользователя: `user`
* Пароль пользователя: `password`
* Пароль root: оставлен пустым

* Перезагрузила виртуальную машину с сетевыми настройками:
```
qemu-system-x86_64 -hda debian.qcow2 -m 2G -smp 2 -device e1000,netdev=net0 -netdev user,id=net0,hostfwd=tcp::1080-:80,hostfwd=tcp::1022-:22
```


* Создала файл конфигурации для PhpMyAdmin:
```

```

```
    ServerAdmin webmaster@localhost
    DocumentRoot "/var/www/phpmyadmin"
    ServerName phpmyadmin.localhost
    ServerAlias www.phpmyadmin.localhost
    ErrorLog "/var/log/apache2/phpmyadmin.localhost-error.log"
    CustomLog "/var/log/apache2/phpmyadmin.localhost-access.log" common
</VirtualHost>
```

* Создала файл конфигурации для WordPress:
```
nano /etc/apache2/sites-available/02-wordpress.conf
```

```
    ServerAlias www.wordpress.localhost
    ErrorLog "/var/log/apache2/wordpress.localhost-error.log"
```

## Ответы на вопросы.
1. **Каким образом можно скачать файл в консоли при помощи утилиты wget?**
Утилита wget используется для скачивания файлов из интернета прямо в командной строке. Основные способы:
   * Базовая команда:
   ```
   wget https://example.com/file.zip
   ```

   * Полезные параметры:
```
# Скачать файл и сохранить под другим именем
wget -O newname.zip https://example.com/file.zip

# Скачать файл в указанную папку
wget -P /path/to/directory https://example.com/file.zip

# Скачать файл в фоновом режиме
wget -b https://example.com/file.zip

# Скачать несколько файлов из списка
wget -i list.txt

# Продолжить прерванную загрузку
wget -c https://example.com/largefile.zip

# Скачать всё с указанной глубины рекурсии
wget -r -l 2 https://example.com/
```

2. **Зачем необходимо создавать для каждого сайта свою базу и своего пользователя?**

Это требование безопасности и изоляции. Основные причины:

Изоляция данных: Если один сайт взломают, злоумышленник получит доступ только к одной базе данных, а не ко всем сайтам на сервере.

Принцип минимальных привилегий: Каждому приложению даются ровно те права, которые нужны для работы. WordPress может работать только со своей базой и не может изменять данные других сайтов.

Упрощение резервного копирования: Можно делать бэкап отдельной базы для каждого сайта.

Удобство администрирования: Легче удалить или перенести отдельный сайт вместе с его базой данных.

Разные версии и требования: Разные CMS могут требовать разные версии MySQL или разные кодировки.

3. **Как поменять доступ к системе управления БД на порт 1234?**

По умолчанию MySQL/MariaDB слушает порт 3306. Чтобы изменить порт на 1234, нужно:
* Изменить конфигурационный файл MySQL
```
nano /etc/mysql/mariadb.conf.d/50-server.cnf
# или
nano /etc/mysql/my.cnf
```

* Найти или добавить строку с портом
```
port = 1234
```

Перезапустить MySQL
```
systemctl restart mariadb
# или
systemctl restart mysql
```

Проверить, что порт изменился
```
netstat -tlnp | grep 1234
```

Обновить настройки приложений
```
define('DB_HOST', 'localhost:1234');
```

4. **Какие преимущества, с вашей точки зрения, даёт виртуализация?**

 С моей точки зрения, основные преимущества виртуализации:

* Изоляция: Виртуальные машины работают независимо друг от друга. Если одна ВМ "падает" или заражается вирусом, остальные продолжают работать.

* Экономия ресурсов: На одном физическом сервере можно запустить множество виртуальных машин, эффективно используя аппаратные мощности (процессор, память, диск).

* Тестирование без риска: Можно экспериментировать с настройками, устанавливать ПО, не боясь сломать основную систему. Если что-то пошло не так — просто удалить ВМ и создать новую.

* Мгновенное развертывание: С помощью шаблонов и снимков (snapshots) можно создать копию настроенной системы за секунды.

* Миграция: Виртуальные машины можно легко переносить между физическими серверами без остановки работы.

* Разные ОС на одном сервере: Можно одновременно запускать Windows, Linux и другие системы на одном компьютере.

* Для обучения: Идеально для изучения администрирования — всегда можно откатиться к "чистому" состоянию.

5. **Для чего необходимо устанавливать время / временную зону на сервере?**

Правильная настройка времени критически важна для сервера по нескольким причинам:

* Логирование: Все события (ошибки, входы, действия пользователей) записываются с метками времени. Если время сбито, невозможно разобраться в хронологии событий при расследовании инцидентов.

* Корректная работа cron: Запланированные задачи (резервное копирование, обновления) запускаются в неправильное время.

* SSL-сертификаты: Они имеют срок действия и проверяются по системному времени. Если время сильно расходится, браузеры будут показывать ошибки "сертификат недействителен".

* Сессии и куки: Веб-приложения используют время для управления сессиями пользователей.

* Базы данных: Временные метки записей (например, дата публикации поста) будут неверными.

* Синхронизация с другими серверами: В распределенных системах важно, чтобы все серверы имели одинаковое время.

7. **Какие есть рекомендации по разбиению диска для серверов? Почему рекомендуется так разбивать диск?**


|Раздел|Размер|Точка монтирования|Назначение|
|------|------|-----------------|----------|
|boot|500 МБ - 1 ГБ	|/boot|Файлы загрузчика и ядра
| (root)|10-20 ГБ	|/ |	Системные файлы, программы
|home|Остальное	|/home|Домашние папки пользователей
|var|10-20 ГБ	|/var|Логи, базы данных, почта
|swap|= RAM или RAM×2|swap|Файл подкачки
|tmp|2-5 ГБ	|/tmp|Временные файлы

**Почему такая схема:**
* Безопасность: Если злоумышленник заполнит логами /var, система не упадет, так как корневой раздел останется свободным.

* Защита от DoS-атак: Атака, заполняющая временные файлы в /tmp, не затронет другие разделы.

* Удобство резервного копирования: Можно делать бэкап только важных разделов (например, /var с базами данных).

* Производительность: Разные разделы можно монтировать с разными параметрами (например, noexec для /tmp).

* Обновления: При переустановке системы можно сохранить /home и /var.

8. **Как перезагрузить Apache Web Server?**

*  Полная перезагрузка (остановка и запуск)
```
systemctl restart apache2
```

* Плавная перезагрузка (без разрыва соединений)
```
systemctl reload apache2
```

* Проверка статуса
```
systemctl status apache2
```
